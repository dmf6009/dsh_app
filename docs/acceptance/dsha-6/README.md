# DSHA-6 UI/UE acceptance evidence (Diff page)

Automated acceptance artifacts for the two UI/UE review blockers (P1-1 Confirm
Dialog accessibility, P1-2 Diff responsive layout). Generated by the headless
Electron harness in `scripts/capture/` against the BUILT renderer with a stub
`window.desktop` (no real runtime, no git, no writes outside this directory).

**Scope / honesty note:** these are **Xvfb/headless captures** of the real
built renderer. They verify layout bounds, focus placement, no page-level
horizontal scroll, and busy-gating in a synthetic DOM. They are **NOT** a
real-desktop 100%/125% DPI human walkthrough — that remains an explicit
regression boundary (see the issue reply), to be confirmed on a real display
before final UI/UE sign-off.

## Regenerate

```
npm run build
xvfb-run -a npm run capture:diff
```

## Artifacts (`.png` + `.bounds.json`)

| File prefix              | What it shows |
| ------------------------ | ------------- |
| `diff-normal-1280/700/500` | Diff page normal state (modified file selected) at the three required viewports; `bounds.noPageHScroll` asserts no page-level horizontal scroll. |
| `diff-binary-1280`         | Binary-file placeholder state. |
| `diff-empty-1280`          | Empty state (暂无文件变更) — returns to Workspace; no toolbar needed. |
| `revert-stage1-1280`       | Confirm dialog Stage 1; `bounds.activeText === "取消"` and `activeIsCancel === true` prove initial focus lands on the safe action. |
| `revert-stage2-1280`       | Confirm dialog Stage 2; focus on the destructive confirm button. |
| `revert-busy-1280`         | Confirm pressed, busy: dialog stays open with spinner/disabled state. |
| `revert-busy-guard-1280`   | While busy, Esc + backdrop click attempted: `dialogOpen` stays true, `dialogBusy=true`, `confirmDisabled=true`, `hasSpinner=true` (not dismissible). |
| `revert-cancel-restore-1280` | Cancel pressed: dialog closed (`dialogOpen=false`) and focus restored to the trigger button (`activeText === "恢复此文件…"`). |

`.bounds.json` also records every `.diff-actions` button rect (no overlap at the
captured sizes) and `pageScrollWidth/clientWidth` for the no-horizontal-scroll
assertion. Monaco's internal content scroll is excluded because its host has
`overflow: hidden`.
